# Capital House requirements

Client-facing documents that collect what Capital House must provide for the build. Version 1 dated 29 October 2026. Replace `[Vendor company name]` before sending.

| File | What it is |
|---|---|
| `Capital_House_Client_Inputs_v1.docx` | Client inputs document, 13 sections: how to use it and when inputs are needed; accounts and access; branding and legal; organisation setup; masters; module by module (28 modules: pages, fields, lists, rules, documents, access, sample data); communication content; reports; data migration; call recording and logging; CRM mobile app store details; decisions pending; checklist of inputs. |
| `Capital_House_Input_Templates_v1.xlsx` | Fill-in workbook, one sheet per entity: Read me, Checklist, Decisions, Branches, Staff, Insurers, Insurer contacts, Products, Lists, Clients, Family members, Policies, Leads, Payments and recovery, Notification templates, Third-party policies, Claims, Investments, Reports, Office phones. Yellow cells are for the client; row 2 of each sheet is an example; dropdowns carry the proposed values from a hidden `_lists` sheet. |

## Regenerating

Both files are generated by `estimation/build/build_inputs.js` from the content in `estimation/build/inputs_content.js`. From the repository root:

```bash
cd estimation/build
npm install
node build_inputs.js
```

The script writes both files into this folder. Edit `inputs_content.js` for wording, fields, lists, rules, decisions and checklist rows; edit `build_inputs.js` only for layout. The value lists in `LISTS` feed the document, the Lists sheet and the dropdowns, so change them in one place.

## Conventions

- Fields marked `*` are mandatory in the proposal. Proposed defaults are marked "our proposal" in the document.
- "Needed by" is relative to the project phases (Week 1, Phase 1 start, Phase 1 testing, and so on) because the delivery timeline is agreed separately.
- Example rows use fictional insurers and a placeholder city; they are labelled as examples.
- Module numbering in section 6 (6.1 to 6.28) is referenced from the checklist; keep the order in `MODULES` if rows are added.
